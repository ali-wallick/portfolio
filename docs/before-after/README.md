# `docs/before-after/`

Paired screenshots of the old DreamHost site and the new one — eight pages, each at a desktop
and a mobile viewport, in `old/` and `new/`. Generated by
[`scripts/capture-comparison.mjs`](../../scripts/capture-comparison.mjs), whose header explains
the capture rules and why the old side is an honest "warts and all" photograph rather than a
repaired one.

**The `old/` half can never be regenerated.** It was captured from the _live_ old site, which
stopped serving at the 2026-08-27 DNS cutover. Run the script today and it can only refresh the
`new/` half. Treat `old/` as an original.

## Two of them are modified, and that is the point of this file

`old/resume-desktop.webp` and `old/resume-mobile.webp` both photographed the old résumé page,
which embedded a full-page render of the 2019 résumé — PO Box and all. The address was legible in
the committed captures until 2026-09-09
([#360](https://github.com/ali-wallick/portfolio/issues/360)).

Both now carry an **opaque, labelled redaction bar** reading `[address redacted]` over that one
line. Everything else in each capture is untouched.

| File                      | Ink measured (x, y) | Bar (w × h at x, y)    |
| ------------------------- | ------------------- | ---------------------- |
| `old/resume-desktop.webp` | 413–613, 429–439    | 219 × 23 at (404, 423) |
| `old/resume-mobile.webp`  | 525–926, 858–879    | 430 × 38 at (511, 850) |

The bar rectangles were derived from the address line's measured ink bounding box (every pixel
with luminance < 150 inside a band containing only that line), then padded — **measured, not
eyeballed**, because three earlier passes at résumé geometry in this repo each returned a
confident wrong answer from a derived number.

Three decisions worth not relitigating:

- **A bar, not deletion.** These are the only photograph of a site that no longer exists. Deleting
  them to remove one line throws away the whole record.
- **A bar, not a re-capture.** There is nothing left to capture.
- **A bar is a real redaction here, unlike on a PDF.** `docs/PRESERVATION.md` warns that a filled
  rectangle over PDF text leaves the text extractable underneath. That is a fact about PDFs, which
  carry a text layer beneath their appearance. A raster has no layer under the pixels: compositing
  happened before encoding, so the covered pixels are gone from the file.

**A modified capture that does not say so is worse than either alternative**, which is why this
file exists and why `docs/PRESERVATION.md` records the same change. The originals remain in git
history; removing them there is [#109](https://github.com/ali-wallick/portfolio/issues/109).

`scripts/check-preserved-blobs.mjs` fails the build if either pre-redaction capture reappears
anywhere in the tree, under any name.
